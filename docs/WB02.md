# WB02：按供应商示例补齐 DSI 时钟通道约束

## 本轮改进

WB01 报告中，`i_mipi_tx_pclk → i_mipi_txd_sclk` 的 setup 裕量为 −0.900 ns。路径从 D-PHY 时钟通道状态机到 `mipi_dp_clk1_HS_OUT[6]`，单周期分析只给出 0.500 ns。白平衡视频通路本身的裕量为 +7.724 ns。

本机 Efinity 2025.1 的供应商示例文件：

`../efinity2025_clean/PFiles/Efinity/2025.1/ipm/ip/efx_dsi/fpga/constraint/ti60f225_demo.sdc`

该示例第 19–21 行采用与本项目相同的字节 / 串行时钟，第 28–29 行对时钟通道 HS 输出使用 setup 3、hold 2 的成对多周期约束。参考文件 SHA256：

`C7E778BF1CAEF44C56EE0E38F16C8F5C3ED1D7006425A6BDF4DB83C1542AE745`

| 参数 | 本工程与供应商示例 |
| --- | --- |
| 字节时钟 | 125 MHz，周期 8.000 ns，上升沿 0.000 ns |
| 数据串行时钟 / 时钟通道 SLOWCLK | 500 MHz，周期 2.000 ns，上升沿 0.500 ns |
| 时钟串行时钟 / 时钟通道 FASTCLK | 500 MHz，周期 2.000 ns，上升沿 1.000 ns |
| 时钟通道接口 | FASTCLK 接 `i_mipi_txc_sclk`，SLOWCLK 接 `i_mipi_txd_sclk` |

WB02 采用这一供应商接口时序约定，进一步把起点限定到 `i_mipi_tx_pclk`、终点限定到两个 DSI 时钟通道的 `HS_OUT[*]`。setup 分析边沿从 0.500 ns 移到 4.500 ns；配套 hold 约束保持原来的 −1.500 ns 分析边沿。约束适用配置由 `tools/check_dsi_constraints.py` 核对，包括参考文件哈希、SDC 时钟、PLL 输出分频 / 相位、接口时钟连接、125 MHz 连续时钟 IP 配置和例外的限定范围。

参考 SDC 的头部版本为 2024.M.263，示例器件模型为 C4；它随本机 2025.1 安装包提供。本工程重新使用 I3 模型布局布线和分析，并保留本板接口设计器给出的 max 0.435 ns / min −0.140 ns 输出延迟。[供应商 DSI 用户指南](https://www.efinixinc.com/docs/mipi-dsi-tx-core-ug-v3.0.pdf)第 9 页给出了 IP 字节时钟与硬块 FASTCLK / SLOWCLK 的连接关系；具体多周期值的依据是上述本地示例 SDC 第 28–29 行。

多周期依据来自供应商示例，不能解释成逻辑速度提高了 4 ns。白平衡像素运算量、流水线延迟、采样统计和帧间除法与 WB01 相同。

## 验证

使用本机 MSYS2 Icarus 12.0：白平衡回归通过 4,423 项像素 / 同步检查，包括除法器、无色偏场景、限幅、原色直通和彩条。详细结果随本轮新构建保存到 `releases/WB02/mipi/`。

Efinity 2025.1.110：map / interface / pnr / pgm 四个阶段通过，生成本轮新的 bit / hex。报告内 14 组 setup、14 组 hold 全部为正裕量。

| 指标 | WB01 | WB02 |
| --- | --- | --- |
| DSI 时钟通道 setup | −0.900 ns，缺少供应商多周期约束 | +2.437 ns，采用匹配的供应商约束 |
| DSI 时钟通道 hold | +1.658 ns | +1.842 ns |
| 视频时钟 setup | +7.724 ns | +7.463 ns |
| 视频时钟分析 Fmax | 152.393 MHz | 146.563 MHz |
| 最小 setup / hold | −0.900 / +0.024 ns | +0.353 / +0.026 ns |
| LUT / FF | 15,948 / 10,315 | 15,948 / 10,315 |
| RAM10 / DPRAM10 / DSP48 | 201 / 4 / 4 | 201 / 4 / 4 |

时序报告的关系汇总仍显示原始 0.500 ns 时钟间隔；路径详情的 `Constraint` 为实际 4.500 ns，表明多周期规则已生效。物理数据路径延迟由 0.683 ns 变为 1.346 ns，此轮不主张关键路径运算加速。约 70 MHz 的视频目标频率不变。

构建脚本同时记录 DSP48；WB01 旧清单漏列的 4 个 DSP48 可由其原始 info.log 核对。

- bit SHA256：`214B75330CCDDC543185F6C0A9E9CDB00A44DBAA277C8D050FD790E343328E94`
- hex SHA256：`15A0BD000C9C227F563F6B249C79247311AADB2952F7A1AEA7BCD27B802ED740`

位流哈希与 WB01 不同，发布文件均来自 `builds/WB02/mipi/` 的本轮完整构建。测试、供应商参考核对、阶段日志和报告一起保存。

## 验证边界和板上状态

供应商 DSI IP 的内部实现为加密源文件。本轮核对的是供应商示例的时序约定，并进行综合 / 布局布线后的静态时序检查，没有用 Icarus 模拟该加密 IP 或板端的 D-PHY 波形。3.5 寸屏的色彩、启停过程和长时间显示仍需现场验证。

本轮不下载 WB02；板上保留此前加载的 WB01。用户目前不能查看板子，JTAG 配置成功或静态时序通过都不能代替画面验收。HDMI 仍未连接，完整连接算法的范围仍为 A8R2 的冻结 640×480 ROI，全部赛题验收尚未完成。

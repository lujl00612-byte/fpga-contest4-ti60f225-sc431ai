## 每版保存规则

- 先阅读 Git 状态和最近的发布清单；保护未提交的用户改动。
- 选择一个可验证的改进，保留独立参考模型和有效回归样例。
- 保存实际测试命令、结果、资源、时序和下载文件 SHA256。
- 有负时序、资源溢出、未接入的模块或未完成现场验证时，明确标注候选 / 待验证。
- 通过必要检查后单独 Git 提交、创建版本标签，不复用旧版本号。
- 若本版失败，保存诊断并修复；不能用旧位流冒充新版本。
- 一次迭代结束清理本次创建的 H: / V: 临时映射。

禁止只改变版本名或随机更换布局种子充当算法优化。固定大小的局部像素窗口本已是 O(1) / 像素，重点优化其比较层数、位宽、存储、流水线和时序；完整连接算法要记录随像素数 P 增长的最坏复杂度。

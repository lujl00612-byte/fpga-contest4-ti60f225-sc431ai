# A15：缓存单元基地址，缩短命中译码路径

## 改动

A14 的最长像素路径从引擎状态经过请求地址选择、除以 5 和缓存字地址比较，到缓存写使能，共 19 级逻辑。A15 给主字和移出字各保存一个单元起始地址，用请求地址减起始地址的结果是否小于 5 判断命中，低三位同时选择单元。

差值保留额外一位，低于起始地址的请求不会因截断而变成命中。主字基地址在 RAM 未命中响应时从已寄存字地址计算；移出字命中交换时，基地址与数据一起交换。捕获、视频、复位和中止写入仍按原规则处理。

640×480 配置新增 2×19=38 位源码元数据。全设计 FF 的变化另见实际构建表，不能直接将物理 FF 增量等同于这 38 位。未增加缓存项数、RAM 块或帧状态容量；接受请求时的 RAM 字地址计算仍保留。

## 实际 Efinity 构建

使用 Efinity 2025.1.110 全新执行 map、interface、pnr、pgm。18 组 setup / 18 组 hold 全部为正。

| 指标 | A14 | A15 | 变化 |
| --- | ---: | ---: | ---: |
| LUT4 | 14,287 | 14,255 | −32 |
| FF | 9,737 | 9,819 | +82 |
| RAM10 / DPRAM10 | 250 / 4 | 250 / 4 | 总计仍为 254/256 |
| DSP24 / DSP48 | 12 / 4 | 12 / 4 | 不变 |
| 最长像素路径逻辑级数 | 19 | 9 | −10 级，最长路径已改变 |
| 报告最长路径 Delay | 5.823 ns | 4.003 ns | −1.820 ns |
| Clock To Q + Data Path Delay | 6.057 ns | 5.367 ns | −0.690 ns |
| 像素域 setup 裕量 | +0.551 ns | +1.241 ns | +0.690 ns |
| 像素域 hold 裕量 | +0.028 ns | +0.026 ns | −0.002 ns，仍通过 |
| 像素域分析最高频率 | 161.734 MHz | 182.050 MHz | +20.316 MHz |
| 全设计最小 setup 裕量 | +0.256 ns | +0.308 ns | +0.052 ns |
| 全设计最小 hold 裕量 | +0.026 ns | +0.026 ns | 不变 |

最长路径现在为 `memory/bank[34].ram → mem_rdata[3]`。两个版本的最长路径起点 / 终点不同，RAM 与 FF 的 Clock To Q 不同，因此表中的 Delay 差值与 setup 差值不相同。结果来自本次布局，尚未经过不同布局的统计或板上计时。

实际像素时钟保持 148.5 MHz，报告分析频率提高没有用于提高实际时钟。构建原始 warning、error、CDC 和布局报告均已保存。

## 周期、复杂度与范围

命中仍为 2 周期，未命中仍为 4 周期；写入在消费 ready 的 ACK 边沿提交。RAM 视频读出两拍，RGB、DE、HS、VS 和独立边缘标记仍为三拍。

| 640×480 场景 | A14 周期 | A15 周期 | 请求数 | 命中数 | RAM 读出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全弱、无强种子 | 1,044,480 | 1,044,480 | 307,200 | 245,760 | 61,440 |
| 全连通 | 11,768,920 | 11,768,920 | 3,372,484 | 2,396,508 | 975,976 |

保留像素、写入、请求、命中、RAM 读出和周期全部与 A14 相同。A15 优化译码路径与时序裕量，处理周期没有减少。按 148.5 MHz 折算处理段仍为约 7.03 / 79.25 ms，未包括冻结、捕获和发布，尚未板上计时。

时间复杂度仍为 O(P)，状态仍为 4P 位加固定缓存 / 控制寄存器。请求上界 `P+10V`、周期上界 `5P+49V+2-2H` 不变，P 为 ROI 像素数、V 为保留像素数、H 为缓存命中请求数。全连通处理段仍超过 60 Hz 单帧预算，全帧实时完整 Canny 尚未完成。

## 独立验证

- 常规回归 320,951 项检查通过，另有初始化延时 bit22 边界验证通过。
- 缓存专项从 351 项增至 388 项，新增缓存基地址前一单元、下一字、末尾字两侧边界和相邻字视频读回。以同一记分板运行 A14 原始 RTL 与 A15，都通过 388 项，命中 100 次、未命中 65 次，数据 / 延迟预期一致。
- 保留主字 / 移出字交换、淘汰、捕获 / 视频失效、复位，以及主字、移出字、未命中写入在 ACK 前中止的检查。
- 17 块供应商 RAM 的 118 项请求数据 / 延迟、76,275 个视频单元；全部 120 块的 736 项请求数据 / 延迟、571,115 个视频单元检查通过，覆盖每拍换地址、跨组、部分末块和视频间隙。
- 跨块快照通过 140,733 项同步、40,320 项彩色输出和 140,733 项独立边缘标记检查，保持三拍对齐。
- 四个 40×80 场景的供应商 RAM、快速模型、A14 重新仿真结果完全一致；640×480 两场景使用已校准快速模型，614,400 个打包单元与独立 BFS 对照通过，计数与保存的 A14 全尺寸记录一致。

发布目录保存 33 个证据文件的 SHA256 / 长度清单，含 A14 源码 / 重新仿真 / 全尺寸基线、对照 JSON、命令、原始报告和新位流。144 个构建输入的原始 SHA256 均核对；相对 A14 只有 `canny_tag_memory.v` 内容修改，39 个输入与 Git 原始字节一致、104 个仅有 CRLF / LF 差异。修改 RTL 的原始字节另行归档。

新 bit / hex 与本次构建输出逐字节一致，分别不同于 A14：

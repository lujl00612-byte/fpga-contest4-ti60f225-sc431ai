# WB03-attempt：独立 RGB888 诊断候选与初始化延时截断

2026-09-30。本候选已完成新的 Efinity 构建，但完整表核对和延时边界仿真发现继承的 22 位计数器截断了初始化延时，**候选被拒绝，不能作为推荐下载版本**。源码、失败诊断和真实构建产物保留在本 Git 标签与 `releases/WB03/mipi_diag/`。

## 本轮新增功能

独立工程 `projects/mipi_diag` 从 WB02 载体建立。两个 DSI 通道分别使用自己的 `pixel_data_en`，由独立计数器生成完整 DE/HS/VS 和每拍两个 RGB888 像素。视频数据不依赖相机、DDR 读出、debayer 或白平衡；载体 PLL、全局锁定复位、DSI 配置和启动延时仍保留。

上方是白、黄、青、绿、品红、红、蓝、黑八色竖条，下方是逐像素橙 / 蓝交替图案，并有一个像素宽白边。低 24 位是像素 x，高 24 位是像素 x+1，最高 16 位为 0；每个像素为 R[23:16]、G[15:8]、B[7:0]。实机颜色顺序、裁剪、方向和效果尚未验证。

V4 **候选**配置：SW0/KEY0 参考 GPIOL_07 用作复位；LED0 GPIOR_27、LED1 GPIOR_24，均为 3.3 V HVIO。去除模式按键、额外 LED 定义，不让复位和模式共用一个管脚。离线审计与提供的 V4 Key XML 方向冲突为 0；实际 PCB 版本和引脚电平未确认。

## 两处初始化问题

1. 原版第一次 ARVALID/ARREADY 握手时，地址仍为 0；`0x24` 在握手边沿之后才生效。原厂源仿真复现该错误。本候选已把地址设置移到 ARVALID 之前；119 次完整写入、每次两次忙状态和一次空闲状态，以及等待 / 中途复位测试通过。
2. 实际初始化表第 166 个零基索引的延时值为 `0x04C4B400 = 80,000,000` 周期；原版 `r_timer[21:0]` 和 `w_reg[21:0]` 比较把它截成 308,224 周期。两个只差延时 bit22 的测试表，在本候选中第二次 AW 握手时间差为 0，参考期望 4,194,304，仿真失败。后续需扩展到完整 32 位延时字段并重新构建。

这是 RTL / 表内容和仿真的结论，未证明是现场无画面的原因。实际 DSI 初始化表与 WB02 逐字节相同；快速 AXI 仿真只缩短延时行并补齐未指定 ROM 行为 0，不能据此验收物理等待时间或 D-PHY 波形。

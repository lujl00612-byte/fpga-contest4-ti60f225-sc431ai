# 3.5 寸 MIPI 独立彩条候选计划

2026-09-30，A12 期间完成离线资料核对。用户不能现场观察，板上仍保留原厂 3.5 寸彩色 Demo 诊断配置。WB03 已按本计划建立独立工程并生成新位流；延时边界检查失败，作为 `WB03-attempt` 保存，详见 `docs/WB03-attempt.md`。下一版修正完整延时字段。实际 PCB 版本及屏幕恢复仍未确认。

## 已核对的 GPIO 差异

对比 `projects/mipi/ti60f225_oob.peri.xml` 与用户资料包中的 V4 `LED_8bit_Test.peri.xml`：

| GPIO | 当前 MIPI 工程 | V4 Key Demo | 后续核对 |
| --- | --- | --- | --- |
| GPIOR_27 | i_arstn 输入，3.3 V、弱上拉 | LED0 输出，3.3 V | 当前复位源是否与实际 PCB 匹配 |
| GPIOR_21 | led[0] 输出 | KEY2 输入 | 按键与 LED 功能映射 |
| GPIOR_22 | led[1] 输出 | KEY1 输入 | 按键与 LED 功能映射 |
| GPIOL_07 | color_keys[0] 输入 | KEY0 输入 | 当前板卡上的 SW0 身份 |
| GPIOL_03 | color_keys[1] 输入 | KEY3 输入 | 当前板卡上的 SW3 身份 |

V4 Key Demo 顶层明确使用 `sys_pll_RSTN = key_i[0]`；当前 MIPI 顶层将 `i_arstn` 送给多个 PLL 和接收端复位。若实际 PCB 符合 V4 映射，复位与 LED 引脚差异需要修正。尚未测量引脚电平，不能据此确定无画面的原因。

`tools/audit_mipi_gpio.py` 可重做本地 XML 对照，输出源文件 SHA256、GPIO 条目及方向冲突。它只读资料文件，不访问板子；A12 发布目录保存了本次审计 JSON。

## 当前彩条的依赖

当前顶层 `video_white_balance` 使用 `rgb_datax2`、`rgb_de`、`rgb_hs`、`rgb_vs`，复位来自 `pixel_data_en`。输出 `balanced_*` 直接送 DSI。白平衡模块的彩条模式替换像素颜色，继续沿用输入视频 DE/HS/VS；它不能单独证明输入同步、DDR、PLL 或屏幕初始化均已正常。

顶层另有一个 `color_bar_rgb` 实例，但配置为 `SYMBOL_NUM=1`、`PAR_PIXEL_NUM=4`，生成四个 8 位符号，服务原 RAW / 帧缓存通路。独立 RGB888 诊断应配置三个颜色符号、每拍两个像素，匹配 DSI 的 48 位像素通路；不能把现有 32 位输出直接接成 RGB888。

## 下一候选版的具体工作

1. 使用匹配 3.5 寸原厂参数的独立视频计数器 / 彩条发生器，输出每拍两个 RGB888 像素及完整 DE/HS/VS；默认启动彩条，避免依赖现场寻找按键。
2. 将独立像素与同步直接接入 DSI，检查 `pixel_data_en`、PLL 锁定、DSI 启停及屏幕初始化的依赖，保留已验证的时钟约束。
3. 单独检查 RGB / BGR 字节顺序和两个像素的次序，用红、绿、蓝、白、黑以及空间变化图案验证。
4. 建立明确的板卡 GPIO 配置；复位、模式按键和 LED 各自使用匹配的映射。若采用 V4 KEY0 作为复位，不同时把同一按键定义为模式切换。实际 PCB 版本仍须在现场核对。
5. 验证完整帧计数、两像素打包、同步、复位和启停；生成新的候选位流、资源 / 时序报告与 SHA256，单独 Git 保存。
6. 用户能够观察且候选有验证依据后，再做独立彩条实机对照。彩条正常后才继续相机 / DDR / 白平衡分段定位；仍无画面时保留现场测量需求。

独立彩条、GPIO 修正和白平衡效果分别记录验收状态，不用静态时序或 JTAG 配置成功替代屏幕画面。
